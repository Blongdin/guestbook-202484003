# 02: 비밀번호 확인 후 삭제 (Delete)

**What to build:** 각 방명록 글의 [삭제] 버튼을 누르면 그 글 아래에 비밀번호 입력 폼이 펼쳐진다. 작성자가 맞는 비밀번호를 입력하면 방명록 글이 목록에서 즉시 사라지고, 틀리면 삭제가 거부되며 폼 안에 "비밀번호가 일치하지 않습니다."가 표시된다. 이미 삭제된 글이면 안내 후 목록이 갱신된다. 화면을 우회해 API를 직접 호출해도 비밀번호가 틀리면 거부된다. smoke 스크립트는 이제 자기가 만든 테스트용 방명록 글을 스스로 정리한다. 세부 계약은 `.scratch/guestbook/spec.md`를 따른다.

**Blocked by:** 01 (방명록 글 작성과 목록 조회)

**Status:** done

- [x] `DELETE /api/entries/[id]`는 `{ password }`를 받아, 맞으면 `200` `{ "ok": true }`, 틀리면 `403` `"비밀번호가 일치하지 않습니다."`, 글이 없거나 id가 양의 정수가 아니면 `404` `"이미 삭제되었거나 존재하지 않는 방명록 글입니다."`, 비밀번호가 누락되면 `400`을 돌려준다
- [x] 비밀번호 비교는 저장된 해시와 `timingSafeEqual`로 한다
- [x] [삭제]를 누르면 인라인 비밀번호 폼([삭제] [취소])이 열리고, 별도의 `confirm()` 팝업은 없다
- [x] `403`이면 폼 안에 빨간 글씨로 안내가 표시되고 비밀번호 칸이 비워진다
- [x] `404`이면 안내가 표시되고 목록이 갱신된다
- [x] [취소]를 누르면 아무것도 지우지 않고 폼이 닫힌다
- [x] `npm run smoke`가 스펙의 smoke 1–3, 6–8단계를 통과한다(틀린 비밀번호 `DELETE` → `403` 후 글 유지, 맞는 비밀번호 → `200`, 이후 목록에 없음, 같은 id `DELETE` → `404`)
- [x] smoke는 도중에 실패해도 마지막에 자기가 만든 테스트용 방명록 글의 정리 삭제를 시도한다
- [x] 01 단계에서 남은 테스트용 방명록 글을 화면에서 삭제해 정리한다
- [x] `npm run build`가 통과한다
